JORNADA+ V5.2 — OPERAÇÃO COM USUÁRIO E SENHA, SEM E-MAIL
========================================================

Este é o Jornada+ operacional V5.2 atualizado. O layout e as funcionalidades
anteriores continuam (ponto, foto opcional, banco, calendário, histórico, relatórios).
A principal mudança é o login por NOME DE USUÁRIO e SENHA, com CÓDIGO de recuperação.

ATENÇÃO: NÃO É SUFICIENTE ENVIAR O HTML AO GITHUB.
O cadastro real precisa do Supabase configurado e da Edge Function implantada.
O modo 'Experimentar demonstração' continua funcionando sem servidor.

CONFIGURAÇÃO DO SUPABASE (UMA VEZ)
---------------------------------
1. Acesse https://supabase.com/dashboard e abra/crie o projeto Jornada+.
2. No SQL Editor, execute o arquivo setup.sql fornecido neste pacote.
   Se o projeto já tem as tabelas, o SQL foi escrito para poder ser reexecutado,
   mas faça backup antes de executar em projeto com dados reais.
3. No Supabase > Edge Functions, crie a função com o nome exato:
   jornada-contas
   Cole o código de supabase/functions/jornada-contas/index.ts.
   Implante com VERIFY JWT DESABILITADO para essa função.
   A função valida o token do usuário ao trocar o código de recuperação.
4. Configure as variáveis secretas da Edge Function no painel Supabase:
   JORNADA_RECOVERY_PEPPER = segredo aleatório de pelo menos 32 caracteres
   JORNADA_ALLOWED_ORIGINS = https://andersonwesley09-alt.github.io
   Atenção: o segundo valor é a ORIGEM do site (SEM /jornada-plus/).
   O Supabase normalmente disponibiliza SUPABASE_URL e SUPABASE_SERVICE_ROLE_KEY.
   Confirme no painel da função; não publique a SERVICE_ROLE_KEY.
5. Garanta que o provedor Email/Senha de Auth está habilitado.
   Ninguém precisará INFORMAR um e-mail no aplicativo. O servidor gera um
   identificador técnico reservado para usar com o Supabase Auth.
6. Em Project Settings > API Keys, copie Project URL e a chave PÚBLICA
   (publishable/anon). Preencha APENAS esses valores em config.js.
7. Publique/atualize os oito arquivos de site no repositório
   https://github.com/andersonwesley09-alt/jornada-plus.
   Settings > Pages > Deploy from a branch > main > /(root).
8. Abra https://andersonwesley09-alt.github.io/jornada-plus/
   Teste CRIAR CONTA e guarde o código. Faça login e registre um ponto.
   Crie uma segunda conta para verificar que os dados ficam separados.

É possível usar o CLI se a tela de criação de funções não oferecer
'Desabilitar verificação JWT':
  npx.cmd supabase login
  npx.cmd supabase link --project-ref SEU_PROJECT_REF
  npx.cmd supabase functions deploy jornada-contas --no-verify-jwt
Use somente o próprio projeto Supabase. Evite colar as chaves secretas em chats.

REGRAS DO CADASTRO
------------------
Nome: 2 a 70 caracteres.
Usuário: 4 a 24 caracteres, começa com letra, pode ter letras, números, _ e -.
Senha: 10 a 128 caracteres.
Código: gerado uma única vez (JP-XXXX-XXXX-XXXX-XXXX).
Sem o código, não há recuperação automática se esquecer a senha.
O código antigo perde a validade quando você o utiliza ou gera outro.
Não compartilhe fotos, senhas ou código de recuperação.

DADOS EXISTENTES
---------------
Esta atualização não apaga registros existentes na conta de demonstração.
No entanto, os dados de demonstração são locais e NÃO migram automaticamente
para uma conta online. Contas anteriores criadas com e-mail também NÃO se
convertem automaticamente para nome de usuário. Preserve seus backups.

SEGURANÇA / LANÇAMENTO PÚBLICO
-----------------------------
- O código de recuperação é salvo no servidor apenas como HMAC SHA-256 com
  segredo privado; nunca em texto simples no banco nem no GitHub.
- O banco aplica RLS para isolar registros e fotos de cada usuário.
- A função impõe limites básicos de tentativas. Para lançamento público,
  adicionar CAPTCHA e proteção contra automação/WAF é recomendado.
- Se usar projeto antigo com dados de produção, faça backup do banco antes
  de executar SQL e valide com duas contas de teste.
- O app não é um relógio eletrônico oficial de ponto.
